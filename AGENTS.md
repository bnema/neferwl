# Repository rules

- Use Go 1.27 only; normal builds and tests use CGO_ENABLED=0.
- Keep a lightweight hexagonal architecture: core imports only stdlib and ports.
- Owner goroutines own window state; no mutex on window state.
- Use zerowrap logging with a `component` field on every entry.
- Run tests with `-race`.
- Use signed conventional commits: `type(scope): description`.

## Mocks (hard rule)

Test doubles are always generated by Mockery v3 (`testify` template). Never handwrite them.

- **No handwritten fakes, stubs or spies.** This covers any test type standing in for a project interface, and function fields swapped by tests (`x.ioctl = func...`). `make check` runs `fakes-check`, which rejects `fake`/`stub`/`spy`/`dummy`/`mock` type names in tests.
- **Every seam is an interface.** When a test needs to replace a dependency, add an interface and generate its mock:
  - Cross-layer dependencies go in `internal/ports`. Mocks: `internal/mocks/ports`, package `portsmocks`, type `MockX`.
  - Adapter-internal seams (e.g. a kernel ioctl) stay unexported in the adapter. Mocks: `<name>_mock_test.go` in the same package.
- **Add a `.mockery.yml` entry** for each new interface, run `make mocks` and commit the generated files. `make mocks-check` (CI) fails if they are stale or missing.
- Use mocks through `.EXPECT()`. Record calls with `RunAndReturn` when a test inspects arguments.
- Channel ports (sealed message interfaces such as `ports.ClientEvent` or `ports.OutputEvent`) are tested by sending messages, not with mocks.
- Not doubles, so allowed:
  - real protocol clients in wayland tests (`wlturbo` proxies);
  - real in-memory implementations of std interfaces (e.g. a locked `bytes.Buffer` as `io.Writer`);
  - production constructor parameters such as `NewRenderer func(w, h) (ports.Renderer, error)`, where tests return a generated mock;
  - channels passed to `app.run` to inject input or observe scenes (channel ports).

- The root `testpolicy_test.go` also detects test types implementing interfaces listed in `.mockery.yml`, regardless of their names, and rejects hand-written `*_mock_test.go` files. Use generated mocks with `Run`/`RunAndReturn` for signaling and recording instead of wrapper types.
- Policy violations temporarily skip with counts while `policyEnforced = false`; flip it after the test migration. Guard fixtures and package-loading errors still fail.

## Time and concurrency

- Run timer, timeout, goroutine-coordination and background-work tests inside `synctest.Test`; use `synctest.Wait()` for quiescence rather than polling assertions or deadline loops.
- Do not use testify `Eventually`/`Never` assertions. `time.Sleep` and real-time waits (`After`, `NewTimer`, `NewTicker`, `Tick`, `AfterFunc`) belong inside a bubble. Drive time with generated `portsmocks.MockClock`/`MockTimer` or the bubble's real `time` package, never a hand-written clock.
- Real wayland sockets, DRM fds and files are real I/O at the adapter edge, not durably blocked bubble operations. Keep these tests outside bubbles and document timer waits with a function doc `// real I/O: <reason>` or `//testpolicy:realtime <reason>`. Both require a reason and neither permits sleeps.
- Never bypass the realtime rule with a helper returning `<-chan time.Time`, `*time.Timer` or `*time.Ticker`: calls to such test helpers count as `time.After` and the helper's annotation does not cover callers. Annotate each function that really waits on real I/O; a helper that encapsulates the whole wait and returns no timer needs one annotation.
- No spin loops: `for` loops calling `runtime.Gosched()`, or `select` with `default` plus a timer deadline, are flagged even in annotated functions and bubbles. Wait on a real event (roundtrip, callback, channel) or use `synctest.Wait()`. Plain non-blocking channel drains are fine.
- A fake-time helper called from bubbles may use `//testpolicy:sleep <reason>` on the sleep line or immediately above it. Do not use this escape to poll real I/O.
- The root guard runs through `go test ./...` in `make check`; generated files, `.worktrees`, `vendor` and `testdata` are excluded. Syntax rules scan all build tags; double detection uses the host platform and active build tags.

## End-to-end tests (headless backend)

Unit tests are not enough for user-facing behavior (binds, gestures, window placement, config keys). Test it end to end on the headless backend before declaring it done; see [docs/dev/headless.md](docs/dev/headless.md).

- Build the branch binary (`CGO_ENABLED=0 go build -o <tmp>/neferwl ./cmd/neferwl`) and run it with a throwaway config: `<tmp>/neferwl --backend=headless --config <tmp>/config --no-xwayland --screenshot <tmp>/shots --input <script> --timeout 10s`.
- Input scripts drive keys and gestures (`key Super+s`, `swipe4 down`, `sleep 1s`); see the table in docs/dev/headless.md.
- Logs go to `$XDG_STATE_HOME/neferwl/runs/headless/latest.log`, not stderr. Read the headless `WAYLAND_DISPLAY` from its `listening` entry.
- Isolate from the user's live session: run the headless compositor, its clients and `neferwl state` with `env -u NEFERWL_STATE -u NEFERWL_SLOT WAYLAND_DISPLAY=<headless>`. `NEFERWL_STATE` wins over `WAYLAND_DISPLAY` and would read the live session's state.
- Check results with `WAYLAND_DISPLAY=<headless> neferwl state` (windows, stash index/count, visibility) and the `latest.png` screenshot.

## Checks before merge

`make check`, `make race`, `make mocks-check` and `staticcheck ./...` must pass.
User-facing changes are also tested end to end on the headless backend.
